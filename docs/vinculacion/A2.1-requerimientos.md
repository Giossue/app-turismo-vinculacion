# A.2.1 Requerimientos funcionales y no funcionales del aplicativo móvil y del agente de IA

## Actores

| Actor | Descripción |
| --- | --- |
| Turista | Usa la aplicación móvil para descubrir, buscar, navegar y conversar con el agente. |
| Administrador institucional | Gestiona fichas, catastro, transporte y publicación desde el panel web. |
| Agente de IA | Responde preguntas usando solo información turística validada y publicada. |

## Requerimientos funcionales — Aplicativo móvil

| ID | Requerimiento | Descripción | Prioridad |
| --- | --- | --- | --- |
| RF-M01 | Registro e inicio de sesión | El turista puede crear una cuenta, iniciar y cerrar sesión. | Alta |
| RF-M02 | Mapa interactivo | Mostrar centros turísticos, puntos de interés y establecimientos sobre un mapa MapLibre con marcadores agrupados. | Alta |
| RF-M03 | Exploración y descubrimiento | Listar destinos destacados y por categoría. | Alta |
| RF-M04 | Búsqueda | Buscar por texto, territorio, categoría y cercanía. | Alta |
| RF-M05 | Ficha pública del centro | Ver descripción, fotografías, horarios, ingresos, accesibilidad y servicios. | Alta |
| RF-M06 | Establecimientos de catastro | Consultar alojamiento, alimentación y agencias cercanas con datos de contacto. | Alta |
| RF-M07 | Rutas y navegación | Calcular la ruta desde la ubicación actual o un origen manual hacia un destino, con instrucciones. | Alta |
| RF-M08 | Transporte público | Consultar cooperativas, recorridos, paradas, horarios y precios referenciales. | Media |
| RF-M09 | Favoritos | Guardar centros, puntos de interés y establecimientos. | Media |
| RF-M10 | Itinerario | Organizar jornadas y paradas de visita. | Media |
| RF-M11 | Opiniones | Calificar y comentar lugares; las opiniones pasan por moderación. | Media |
| RF-M12 | Modo sin conexión | Descargar un paquete por ciudad para consultarlo sin internet. | Media |
| RF-M13 | Perfil y ajustes | Gestionar el perfil, las preferencias y los permisos de ubicación. | Baja |
| RF-M14 | Chat con el agente | Acceder al asistente turístico desde la aplicación. | Alta |

## Requerimientos funcionales — Agente de IA

| ID | Requerimiento | Descripción | Prioridad |
| --- | --- | --- | --- |
| RF-IA01 | Chat conversacional | Responder en español con la voz de un guía turístico, mediante `POST /api/v1/ai/chat` y streaming SSE (`/ai/chat/stream`). | Alta |
| RF-IA02 | Respuestas fundamentadas | Consultar únicamente contenido publicado y validado mediante herramientas del backend. | Alta |
| RF-IA03 | Búsqueda de lugares | Buscar centros y establecimientos publicados (`searchPlaces`). | Alta |
| RF-IA04 | Detalle de lugar | Entregar horarios, ingresos y datos del centro (`getPublishedCenter`). | Alta |
| RF-IA05 | Cercanía | Recomendar lugares cercanos a la ubicación aproximada del usuario (`searchPlaces` con `nearby`). | Alta |
| RF-IA06 | Solicitud de ubicación | Pedir permiso de ubicación cuando la pregunta lo requiera (`requestLocationAccess`). | Media |
| RF-IA07 | Tiempos y rutas | Estimar tiempos en auto, a pie y en bicicleta, y calcular rutas viales (`getTravelTimes`, `calculateRoadRoute`). | Media |
| RF-IA08 | Transporte | Informar sobre el transporte público hacia un centro y las paradas cercanas. | Media |
| RF-IA09 | Tarjetas y acciones | Acompañar la respuesta con tarjetas de lugares, acciones («Ver», «Cómo llegar») y fuentes. | Alta |
| RF-IA10 | Historial | Guardar y recuperar las conversaciones del usuario (`conversaciones_ia`, `mensajes_ia`). | Media |
| RF-IA11 | Apoyo editorial | Ayudar a los administradores a redactar y validar contenido de las fichas. | Baja |

## Requerimientos no funcionales

| ID | Categoría | Requerimiento | Criterio de aceptación |
| --- | --- | --- | --- |
| RNF-01 | Plataforma | Aplicación nativa Android/iOS con React Native y Expo. | Compila con un development build de Expo en Android. |
| RNF-02 | Rendimiento | La API pública responde con rapidez. | p95 < 400 ms sin proveedores externos. |
| RNF-03 | Rendimiento | La carga del mapa está limitada al área visible. | El endpoint de viewport no devuelve fichas completas. |
| RNF-04 | Rendimiento | Las imágenes están optimizadas. | Fotos convertidas a WebP con tamaños derivados. |
| RNF-05 | Seguridad | Comunicación cifrada y autenticada. | HTTPS y token de sesión; roles verificados en la API. |
| RNF-06 | Seguridad | Las claves de IA nunca están en el cliente. | `OPENAI_API_KEY` y `ANTHROPIC_API_KEY` existen solo en la API. |
| RNF-07 | Seguridad de la IA | El agente solo usa herramientas permitidas (allowlist). | El modelo no escribe coordenadas, tarjetas ni direcciones; el backend las rehidrata. |
| RNF-08 | Veracidad | La IA no se convierte en fuente de verdad. | Toda tarjeta proviene de datos publicados con fuente trazable. |
| RNF-09 | Privacidad | La ubicación es opcional y aproximada. | Sin GPS de alta precisión fuera de la navegación activa. |
| RNF-10 | Disponibilidad | Funcionamiento parcial sin conexión. | Paquete offline por ciudad. |
| RNF-11 | Usabilidad | Interfaz en español, responsiva y accesible. | Se cumple la lista `docs/quality/mobile-checklist.md`. |
| RNF-12 | Mantenibilidad | Monolito modular con capas dominio/aplicación/adaptadores. | Los controladores no contienen reglas de negocio. |
| RNF-13 | Portabilidad de la IA | Proveedor de IA reemplazable. | Se cambia con `AI_PROVIDER` (openai/anthropic) y `AI_MODEL`. |
| RNF-14 | Auditoría | Trazabilidad de los cambios administrativos. | Tablas `auditoria_fichas` y `auditoria_catalogos`. |
| RNF-15 | Calidad | Pruebas automatizadas. | Pruebas unitarias con Vitest en el móvil y la API. |
