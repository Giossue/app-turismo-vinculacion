# Revisión de interfaz

- Brief de usuario, decisión, datos mínimos y acción principal.
- P0/P1 claros, detalles graduales y consecuencias visibles.
- Componentes/tokens nativos o MUI según el repositorio real.
- Carga, vacío, error, offline, texto largo, cancelación y reintento.
- Estado remoto/local, cambios de identidad y respuestas tardías.
- Permisos contextuales, alternativa sin GPS y liberación de seguimiento.
- Historial de pantallas separado de overlays y gestos.
- Texto ampliado, safe area, teclado y objetivos táctiles accesibles.
- UI refleja autorización; ninguna decisión privada depende solo de un botón.
- Contrato compatible con API y el otro cliente cuando corresponda.

Las comprobaciones ejecutadas se acuerdan con el alcance solicitado y se reportan.
Procedimientos existentes: [móvil](mobile-checklist.md),
[responsividad](mobile-responsive-checks.md) y [coordinación web](web-checklist.md).
